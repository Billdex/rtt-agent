# 线 A · 策略迭代

> 目标：**用日志证据把"收益/回合"推上去，并且让这套推进方法本身可复用。**
> 这条线是本项目的第一目标，但它**不等于"每轮都要开局"**。

## 两层产出，不要混

| 层 | 产出 | 验收方式 |
| --- | --- | --- |
| **方法层（可复用）** | 一套流程 + 判据 + 脚本，别人拿去也能跑 | 新人只看 `QUICKSTART.md` 就能跑完一轮；判据是数字不是感觉 |
| **结果层（本账号）** | 某张图上的具体参数组合 | 全样本 GB/回合 提升，n 足够，且可归因到单一变量 |

**工具改动不属于策略轮。** 只有当"工具挡住了策略推进"时才修工具，而且**单独开一张工具任务单**：
不计入策略轮次、不与策略改动同批、不写进策略轮的战报结论里。
判断标准：这次改动会让"某个玩家决策"变好吗？会 → 策略；只是让脚本能跑 → 工具。

## 一轮的固定动作

```
0) 领任务单（playbook/task-template.md），写明：唯一变量 + 判据数字 + 需要人类做的事
1) preflight              → 任一 FAIL 就停（属于线 B，先转过去处理）
2) strategy-snapshot      → 记下改动前的机器凭证
3) 开局（走 H-02）        → 优先游戏自带自动加入
4) 局中只读               → 可刷新、可跳页，绝不点撤离类按钮（T-01）
5) 结束：analyze-log      → 读日志尾部 + 结局定位取最后一条命中（M-01）
6) 归因 → 只改一个变量     → 写不出"因为第几局的哪条日志"就不改（M-02）
7) 结案：更新 STATE + report + 任务单
```

**局中盯进度**只用 `raid-watch.mjs`（T-15），不要手写循环，不要用 `| tail` 判退出码。

## 允许动的变量（白名单）

只在下面这张表里选，一次一个。表外的参数要动，必须先补进本表并说明依据。

| 变量 | 当前值 | 动了会影响什么 | 已知依据 |
| --- | --- | --- | --- |
| 弹种（穿深） | 5.45 PS | 能不能打穿 | G-09 / G-10 |
| `负重门槛` | 90% | 实际最先触发的撤离闸 | G-11 |
| `硬撤离 剩余` | 80 | 空走回合数 | G-07 |
| `软撤离 剩余` | 120 | 提前离场概率 | G-12 |
| `血量低于 N% 撤离` | 30% | 治疗窗口被打断的风险 | G-08 |
| `交战撤退血量` | 35% | 同上 | G-08 |
| `priorityNodes` | `{}` | 走哪些点 | G-13 / G-15 |
| 地图轮换 | 仅旧城区 | 风险基数 | G-06 |

**不在白名单里、需要单独任务单的**：配装（属于线 B）、地图新增（属于实验设计）、携弹量（等 H-A1 结案）。

## 禁止

1. **策略轮内动配装**——那会同时改变"打不穿"与"收益密度"，本轮作废（G-10 的教训）。
2. **策略轮内改工具**——工具改动会改变度量，前后数据不可比。
3. **一轮验证多个假设**——WIP=1（M-07）。
4. **用子集样本宣布改善**——M-03。
5. **把"跑了 N 局"当成果**——成果是判据数字变了。

## 完成判据（三级，必须前一天想清楚）

| 级别 | 判据 | 结论怎么写 |
| --- | --- | --- |
| 无效 | 判据数字没动，或方向相反 | "该变量不影响 X，已排除" —— 这也是有效产出 |
| 有效但不可归因 | 数字变好，但同期有其他变化 | "疑似有效，需单独复跑一次" |
| 可结案 | 单一变量 + 全样本 + n 足够 | 写进 `LESSONS.md`，更新 `STATE.md` 主指标表 |

「分辨不出来」也是合法结果：写"未区分，放弃该变量"并列进已结案，不许无限挂起。
