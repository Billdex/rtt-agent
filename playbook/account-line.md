# 线 B · 账号经营

> 目标：**让这个账号随时处于"能打仗、不欠账、不丢不可逆资产"的状态。**
> 这条线**不需要开局**，多数动作在仓库/商人/任务页完成，几分钟一轮。

## 五条健康线（每轮开始先读一遍，数字在 `progress/STATE.md` §2）

| 健康线 | 判据 | 越线时的动作 |
| --- | --- | --- |
| 现金 | ≥ 300,000（自动加入保险丝） | 先清库存/交任务，不要靠跑局补 |
| 仓储 | < 200 L，且未满 400 L 上限 | 按 G-26 顺序：先扩容 → 清重复品 → 最后变现 |
| 医疗 | 血液满、低部位 0 | 开局前治疗（报备 H-04） |
| 出战完整 | 11 / 11 槽位、`preflight` 0 FAIL | 加载配装 1（缺口 0）；补不回来的件走替代件 |
| 任务 | 无"可提交"积压、无"可接取未接" | 先清三态（G-27），再接新任务 |

## 每轮例行（3 条命令，只读）

```bash
node ai-raid-agent-kit/scripts/preflight.mjs      # 槽位 / 负重 / 现金 / 仓库 / 携带价值
node ai-raid-agent-kit/scripts/quest-scan.mjs     # 三态任务
node ai-raid-agent-kit/scripts/rtt.mjs text 1500  # 当前页面（仓库体积、治疗报价）
```

读完填 `STATE.md` §2，只改数字，不加叙述。

## 三类动作，别混着做

| 动作 | 定义 | 频率 | 是否需要开局 |
| --- | --- | --- | --- |
| **维持** | 治疗、补弹、补药、修甲、加载配装 | 每轮开工前 | 不需要 |
| **优化** | 换装、升级胸挂/背包/护甲、改配装绑定、点任务 | 有明确缺口时 | 不需要 |
| **清理** | 清仓库、卖重复品、交任务消耗库存 | 体积越线时 | 不需要 |

三类动作全部**在策略轮之外**完成。做完再开策略轮。

## 决策规则（避免"花钱买教训"）

1. **加装备前先问"这件死了还能不能买回来"**（G-05）。买不回来的按一次性消耗品记账，不当资产。
2. **换容器顺序**：先换容器 → 再从仓库把弹药药品塞回新容器（G-19）。顺序反了物资会跟着旧容器回仓库。
3. **配装改动必须"先穿成目标状态，再快照"**（G-18）。不要试图字段编辑。
4. **白买检查**：配装字段与身上实际穿戴不一致时，每次加载都会白买（G-17）。局内自动换装后回头对齐。
5. **仓库满先扩容再清仓**（G-26）：15 万保住 1.9 M 原值，优于按 59–66% 折价。
6. **任务先接再捡**（G-28）：未接取的任务物不在 `keepNeeds` 保护名单里，会被自动出售。
7. **交任务前确认库存**：上交类任务消耗 FIR 存量（G-27 副作用 ①）。

## 与线 A 的互斥（最重要的一条）

**同一轮里只能有一条线是"主推进"。**

| 情况 | 允许 | 不允许 |
| --- | --- | --- |
| 本轮是策略轮 | 做"维持"类动作（治疗/补弹） | 换装、改配装、改策略参数 |
| 本轮是经营轮 | 冻结策略参数与地图轮换；可清理、可升级 | 开局跑批次、改策略参数 |
| 维持动作意外改动了变量 | 在任务单里标注"本轮不可归因"，只记账不比指标 | 假装本轮是干净实验 |

理由：**换配装会同时改变"打不穿"与"收益密度"**（G-10 就是两变量同改导致无法拆分的实例）。

## 完成判据

| 任务类型 | 判据（必须是状态变化，不是"我做了"） |
| --- | --- |
| 重装 / 治疗 | `preflight` 0 FAIL · 11/11 槽位 · 缺口 0 项 |
| 清仓 | 体积 < 200 L 且总价值下降比例在预期区间内 |
| 接任务 | `quest-scan` 中该条从「可接取」变「进行中」 |
| 配装优化 | 加载后 `preflight` 全 PASS，且"无法补购"件数不增加 |

写完判据才能收工；数字没到就是没完成，不许写"基本完成"。
