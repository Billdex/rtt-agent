# 工具与操作层知识（T 编号）

> **这份文件不参与任何游戏决策。** 它只回答一件事：*怎么让脚本和页面按预期动起来。*
> 与 `LESSONS.md`（游戏知识）、`playbook/method.md`（实验纪律）严格分开，别互相搬。

## 写入 / 淘汰规则

- **只有"仍然会挡住操作"的东西才留下**，形如：选择器怎么定位、受控组件怎么填、哪个按钮有同名、哪类判断会假阴性。
- **一次性的 bug 记录不许进**：修好之后只在 `progress/report.md` 的「本轮改动」里留一行，git 里有完整 diff。
- 每条尽量压到 3 行以内：**现象 → 可靠做法 → 怎么校验真的生效了**。
- 凡是写成"记得小心"的，改成一条可执行的动作，否则等于没写。
- 新增条目前问一句：**这条会影响玩家/我们做的一个游戏决策吗？** 会 → 去 `LESSONS.md`，不要留在这里。

## T-01 按钮点击红线：先读文案，再点

- 战局中点「手动撤离」= 【匆匆撤离】，经验减半。**整页刷新 / `goto` 跳路由与离场无关**，危险的是盲点按钮。
- 任何按文本定位的点击，文案命中 `撤离 / 放弃 / 投降` 一律不点。
- 校验：点完读页面状态，确认不是"撤离中"。

## T-02 容器批量操作的作用域

- 「全部移到仓库」作用于**整个容器**，不是那一件（点一次清空胸挂，得重装一遍）。
- 要单件/定量，走 T-03 的转移模式。

## T-03 精确数量转移

- 普通模式「放入胸挂」= 整堆移动；**数量输入框只在「转移模式」弹出的对话框里存在**。
- 校验：改完读 `携带总价值` 的增量，对得上才算成功。

## T-04 受控组件：赋值一律要走真实键盘

- React 受控组件不认 `input.value = x`（原生 setter 也可能被后台刷新冲掉）。
- 可靠做法：`focus` 后 `rtt.mjs key Meta+a` + 逐位 `key <数字>`；或 Playwright `type`。
- 校验：**保存 → 整页 `goto` 重载 → 再读一次**。改完那一刻的 DOM 值不算证据。

## T-05 下拉框取值看 `select.value`

- 页面正文只渲染**全部选项**（`当前策略|搬运工|222|空`），看不出选中项。
- 必须 `eval` 读 `select.value` 才知道真实绑定——"以为改好了其实没改"多半是这里。
- 校验：改完重载再读 value。

## T-06 按需渲染的配置区

- 自动出售的 22 个类型勾选框、价值区间、稀有度上限，**只在主开关打开后才渲染**。
- "关着时只看到 2 个复选框"≠ 不可配置。评估一个配置项之前，先把开关打开再看。
- 反向注意：自动加入一开就倒计时，**先改完配置再开开关**。

## T-07 表单数字输入：祖先匹配会打错框

- 「向上找含该文案的祖先，再取其中唯一 input」会命中整个表单区：实测把「两局间隔」改成了 3（应 ≥10）。
- 可靠做法：`textContent.trim().startsWith('精确文案')` 定位标签 → 逐级向上找**只含一个 input** 的容器 → 含多个就报失败，不要瞎选。
- 校验：重载后**同区三项一起读**（间隔 / 最多局数 / 资金下限），只对一项不算通过。

## T-08 滑杆：循环"读-按-读"，达标立刻保存

- 键盘步进会跳变（连按 4 次该到 75，实测读到 75 再按一次变 65）；原生 setter 赋值会被后台刷新覆盖回原值。
- 可靠做法：循环「读当前值 → 未达标按一次 ArrowRight → 再读」，达标**立刻点保存**，然后 `goto('/strategy')` 复核。
- diff 可能因数组顺序变化报出两条，实际只有一条语义改动：**按内容读，不按条数读**。

## T-09 同名按钮：只认最后一个

- 仓库「放入胸挂」有两个同名按钮，只有**详情面板末尾**那个生效；前几个点了没反应，会白重启循环。
- 取出 `×N` 要先点物品名那一行 → 弹数量框 → 再点「移至仓库」。
- 注意「物资视图」列出的是**出战携带物**，不是仓库。

## T-10 批量出售的浮层与成交校验

- 单件：`快速出售` → 同面板变 `确认出售` → 成交。
- 堆叠（数量 >1）：弹出独立浮层 `.qty-backdrop`（内含 `.qty-field`，默认全部）→ 点**该浮层**的「出售」。Playwright 默认 dismiss 原生对话框，早先批量脚本因此只卖掉单件、日志却显示"已点"。
- 可靠做法：显式识别 `.qty-backdrop` → 点浮层内按钮 → **校验卡片真的消失**。`element.click()` 不做命中测试，"点了"不是"生效了"。
- 报价不等于到账：护甲按耐久折（实测四件 JPC 分别 48% / 28% / 57% / 60%）。要报预期只能给区间。

## T-11 配装只有整份快照，没有字段编辑

- 槽位是只读文本（`loadout-slot-item`），唯一写入口是「保存当前到配装」：整份覆盖"当前 8 槽 + 当前携带物资"。
- 想改一个字段：先让身上变成目标状态 → `部分加载配装` 补满物资 → 手动换件 → `保存当前到配装` → 重开面板核对"缺口 0 项"。
- 副作用：快照会把"能否补购"一起记进去，商人买不到的件会被标「无法补购」。

## T-12 页面数值会滞后

- 任务页页头现金提交后不刷新（实测 +64,000 要到 `/raid` 才看到）。
- 任何"钱/经验有没有到账"的核对，**换页重读**，别在同一页连读两次。

## T-13 `analyze-log` 的三类统计假象（已知局限，不是 bug）

- **敌人被算进自己**：敌人的换弹/开火同样写成 `已经换好弹` / `开火`，`装填` 与 `开火` 只能当交火强度代理，**不能用来算弹药预算**。
- **详情页只渲染部分日志**：293 回合的局只渲染 112 条（首条 `[8]`、末条 `[293]`），聚合值只是抽样；`logTurns < 回合数×0.8` 时脚本打 `[warn]`。归因**只看尾部**。
- **玩家名靠三级回退**：`RTT_PLAYER` → `/api/me` 的 `account.nickname` → 页脚。任一级失效都会让 `hitsTaken` 静默变 0（看起来像"从没被击中"）。
- 换语言或改文案会让中文关键词失配。

## T-14 详情面板必须做身份校验

- 点开某局后**不要等固定毫秒**：等「头部出现 `<地图> · N 回合`」**且**「`战局收益` = 列表行金额」双判据。
- 只等回合数不够：上一局面板会残留，看起来"解析成功"但数字是别人那局的。实测详情区 105 ms 就绪，**等更久没用，必须校验身份**。
- 8 秒超时重点一次；仍失败打 `[warn]`，汇总显示 `? 回合`，稍后重跑或手工点详情。

## T-15 盯批次：只用 `raid-watch.mjs`，且必须看退出码

```bash
node ai-raid-agent-kit/scripts/raid-watch.mjs --every=45 --minutes=12 > /tmp/rw.log 2>&1; echo $?
```

- `0` = 批次真的结束；`2` = 到 `--minutes` 上限；`no-raid-seen` = `--grace`（90 s）内一次没抓到战局。
- 尾部延迟 ≈ `--every + 8s`（空闲用 8 秒短轮询），**这个量看 `summary.lagSec`**，别凭感觉说"游戏慢"。
- **禁止手写 bash 循环**：总时长超过单条命令时限就会被外部截断，现象像"脚本卡住、要人工结束"。总时长必须写成参数。
- **禁止用 `| tail` 判退出码**：`$?` 会变成 `tail` 的 0，`0/2` 语义当场失效。要判就重定向到文件再 `echo $?`。
- 每个采样 append 到 `progress/raid-watch-YYYY-MM-DD.jsonl`，进程被杀也不丢证据。
- 单次采样"无战局"、下一行又回到战局 = 跳转与渲染抢跑，**假阴性**；脚本要求连续 `--idle` 次空闲才判结束。

## T-16 脚本自己会撒谎：取值失败会静默变空

- 凡是 `|| ''` 兜底的字段，**第一次用到时必须亲眼确认非空**（实测 `preflight` 血量上限硬编码 100，LV7 后永久 WARN；`携行总价值` 正则写成"携行"，字段一直是空）。
- 正则别写死中文近义词，面板文案随版本变（携行 → 携带）。
- 判满血用 `当前 / 上限` 比值，不要比固定数字。
- 两个回合后的通用动作：**让脚本打印它读到的原始串**，不要只打印结论。
