# 经验教训（全部来自实测，附证据）

这份文件是整套包里最值钱的部分。脚本谁都能写，坑不是。

## 一、操作类

### 1. 战局中点「手动撤离」= 提前离场

日志原话：`【匆匆撤离】已撤出战局，带出物资价值 134,000，本局经验减半。`

- 「手动撤离」是战局内**可点击按钮**，不是标签
- 点下后：**立即打断当前搜索流程，改为向撤离点移动**；撤离按半价结算，收益与经验同时砍半
- 刷新页面 / `page.goto` 跳路由**与离场无关**：战局进行中跳页实测仍能正常撤离（带出 31 件 FIR、+283,005 GB）
- 危险的是"盲点按钮"，不是"导航"
- **硬性约束**：战局中永不点击「手动撤离」；任何按文本定位的点击都要先读文案，排除 撤离 / 放弃 / 投降 类操作

### 2. "全部移到仓库"会清空整个容器，不是那一件

我点了一件止血带的"全部移到仓库"，结果整个胸挂被搬空，于是不得不重装一遍。
→ 批量操作前先看按钮文案的对象范围。

### 3. 数量输入只在"转移模式"的对话框里出现

普通模式点"放入胸挂"是整堆移动；要精确数量必须先进转移模式，弹出的对话框里才有数量输入框。
→ 想带 4 个止血带而不是 27 个，靠的是这个对话框。

## 二、配置类

### 4. 配装绑定会被重置，必须每次核对

现象：把地图的"装备配置"设成配装 2 并保存，过一会儿又变回 `0 = 当前装备/默认套件`。

后果很隐蔽：默认套件指向"配装 1"，而配装 1 只有装备、没有物资清单 → 局内**看不到子弹、也不补弹**，玩家以为是游戏 bug。

修复清单：
1. 改完绑定后**整页重载再读一次**，确认值还在
2. 局后去物资视图看胸挂：应能看到弹药数量、负重应在预期值附近
3. 把"配装 1"也覆盖成同一套，作为兜底

### 5. 加载配装会按缺口扣钱

"缺口 0 项 / 费用 0 GB" 才是不花钱。有缺口时会自动购买，收益会被吃掉一部分。
→ 每轮结束核对：现金变化 ≈ 战局收益 − 维修/治疗/补货。

## 三、分析类

### 6. 结算数字说明不了原因，必须读日志

同样是"撤离成功"，原因可能是：
- 弹药耗尽（日志：`已无弹可用，改往 XX 撤离`）
- 药品耗尽（日志：`缺少能处理当前伤势的药品`）
- 容器满（规则触发）
- 到达回合上限

三种原因对应三种完全不同的修法。**只看结算就会改错参数。**

### 7. "带出物资价值" ≠ "本局收益"

前者含身上装备与已有物品的估值，后者才是净收益。
曾出现"带出 219,500 / 结算 +8,000"，我误判为账目异常，实际是口径不同。

### 8. 击杀数 ≠ 收益

| 局 | 击杀 | 收益 |
| --- | --- | --- |
| A | 4 | +193,900 |
| B | 0 | +265,700 |
| C | 6 | +96,200 |
| D | 2 | +210,740 |

两组独立样本都指向同一结论：**收益主要由"单位时间带出的价值密度"决定，不由击杀决定**。
追打会同时消耗弹药、时间和血量，是三重成本。

### 9. 死亡成本是可以量化的

两次实测：−119,700 与 −137,000，与"一整套装备的重置价"（≈148,000）吻合。

盈亏平衡式：若激进打法单局多赚 ΔG，死亡损失 L，则死亡概率 p < ΔG / (G + L) 时激进更优。
代入 ΔG≈70,000、G≈220,000、L≈148,000 → p < 19%。实测死亡率 1/7 ≈ 14%，说明**"允许偶尔死"在经济上是站得住的**。

### 10. 风险主要来自地图，不是策略松紧

- Togov 外环：5 局 0 死
- Togov 交通枢纽：2 局 0 死
- 旧城区：2 局 1 死
- 边境检查站：1 局 1 死

先筛地图，再谈参数。

## 四、自动化类

### 11. 游戏自带调度 > 外部脚本

有"自动加入战局 / 进局前自动治疗维修 / 地图轮换 / 结束后自动出售"就别用脚本点按钮。脚本只做分析与调参。

### 12. 定时巡检比后台监控稳

后台长期监控脚本有两个死法：页面一变就误判"战局结束"、以及跨会话收不到完成通知。
→ 用"每 N 分钟一次的定时检查 + 局间窗口操作"，并且**暂停时把定时任务删掉**，否则会空转刷屏。

### 13. 一次只改一个变量

同一轮里既换地图又改撤退线又换配装，收益变化就无法归因。改动要能写成"因为第 X 局的哪个日志现象"。

### 14. 自动加入的开关就是"开局"按钮

自动加入在 `/raid?tab=auto`（标签叫「自动策略」），总开关是 `button.auto-enter-toggle`，未启用时按钮文案就是
`满足条件自动加入战局 / 未开启`。**读状态时只能读、不能点**——点一下就开始跑局。
同页可读到的参数（默认值）：两局间隔 10 分钟（最低 10）、最多自动进入 100 局、资金低于 100000 GB 暂停、
自动治疗 / 自动维修 = 开（维修阈值 80%、耐久下限自动替换 = 关）、结束后自动出售 = 关、入库前自动拆卸武器配件 = 关。
"已自动进入 6 局 · 最长 24 小时"是计数与时长上限，不是当前开关状态。

### 15. 「高级模式」不是只读 JSON 视图，它会把策略变成 Lua

策略页右上角 `高级模式` 是勾选框，勾上会弹窗：`高级模式下，之前的自定义配置将失效，由 Lua 策略接管。
初始代码会包含当前基础配置，原配置保留为备份。保存后生效。`——这是**破坏性**开关，不是"看 JSON 的按钮"。
想读策略原文只能点旁边的 `JSON` 按钮；被弹窗挡住时先点 `取消`（`modal-backdrop` 会拦掉所有点击 10 秒超时）。
策略槽位里 `基础` = 表单模式，`Lua` = 已被接管（实测槽位状态：`搬运工|基础`、`222|Lua`、`3|空`）。

### 16. 每图装备绑定会不一致，且读法要按 select 的 value 读

实测 6 张图的绑定：外环 / 交通枢纽 / 机场 = `配装 2`（select value=2），
旧城区 / 边境检查站 / 发电站 = `当前装备 / 默认套件`（value=0）；策略一律是 `当前策略`（value=0）。
从页面正文只能读到下拉框的**全部选项**（`当前策略|搬运工|222|策略 3（未保存）`），看不出选中项，
必须 `eval` 读 `select.value` 才知道真实绑定 —— 这就是"以为改好了其实没改"的根源。
配装 1 实测有物资清单（5.45 PS×215 自动购买、止血剂×4、医疗包×2、夹板×2、止血带×5），
缺口 2 项 / 预计费用 13,744 GB —— 和旧结论"配装 1 只有装备没有物资"不一样，加载前必须逐项核对缺口与费用。

### 17. 自动出售的细分选项只在"打开开关后"才渲染

`/raid?tab=auto` 底部的 `auto-sell-section` 默认只显示 2 个复选框，**勾上「战局结束后自动出售」才会渲染**
22 个类型复选框 + `最低单件价值` / `最高单件价值` / `自动出售稀有度上限`。
"开关关着时看不到选项"= 不代表没有选项，别据此下"不可配置"的结论（我第一次就判断错了）。

可读到的规则原文：

- 主开关：`只处理成功撤离带回的新 FIR 物品；仓库旧物不卖，价值按单件计算。未开启自动拆卸时，带配件的武器按整机判断。`
- 拆卸开关：`先拆下本局新带回武器的全部配件，再分别判断枪和配件是否自动出售。未售出的物品按原规则入库；穿戴中的武器、带入物品和锁定物品保留。`
- 稀有度：`更高稀有度的物品不会自动出售`（`all/common/uncommon/rare/epic/legendary`）
- 价值区间：`最低单件价值 0`、`最高单件价值 0 为不限`（按单件算，不按整堆）

因此它**没有**"按任务/按收藏"的白名单，真正起保护作用只有四条：
① 只碰本局新带回的 FIR（存量旧物不动）② 穿戴中/带入/锁定 ③ 策略里 `keepNeeds`（任务与建筑需求物品在战后自动出售时保留）
④ 稀有度上限。→ 保护任务物品唯一可靠的做法是**先把该任务接下来**（未接取的任务需求不在保护名单里）。

- 类型全不选的含义（=不卖任何类型 or =卖全部）**未验证**；稳妥做法是显式勾选要卖的类型，别依赖空集合语义。
- 未验证：`匆匆撤离` 是否算"成功撤离"（若不算，半价局仍会堆仓库）。

### 18. 任务要按"三态"扫，不是只看"可接取"

`quest-scan.mjs` 每行末尾的状态词才是判据：`接受`（可接取）/ `提交`（条件已满、点一下就结钱）/ `目标未完成`（进行中）。
只筛"可接取"会漏掉已经 100% 的进行中任务——实测漏了 3 个满进度任务，补交直接拿回 **+137,000 GB**（53,000 + 49,000 + 35,000）。

还有一类最值钱的：**可接取但条件已经满足**的任务。实测「机场：补给线」可接取、电线 3/3 早已在手，
接取 → 立刻变 `提交` → 再交，净得 **+59,500 GB / 645 XP**，中间不需要任何一局。
→ 每轮固定动作：先扫三态，把"接受 + 立刻提交"的清完，再谈开局。4 个任务合计 **+196,500 GB / +2,085 XP**（现金条核对完全一致）。

注意两个副作用：① 上交类任务会**消耗仓库存量**（锯木厂：补给线 上交 2 个止血剂 FIR），交之前确认医疗库存够用；
② 交完会解锁后续任务（机场：路口 → 机场：补给线），同一条链可以连着吃。

### 19. 仓库会先满，满仓会静默吃掉收益

实测仓库占用 `199.1 L / 200.0 L`（124 件），此时"战局结束后自动出售"仍是**关**。
后果：撤离带回的 FIR 物品无处可放，`撤离后副武器入库` 这类开关也会失效。
→ 每轮开始先看仓库占用；接近 200 L 就先开自动出售或手动清仓，再谈调策略。
（人类手动卖掉 21 件后降到 `156.5 L / 103 件`，腾出 42.6 L —— 手动清仓一次就能换 1–2 局的空间。）

### 20. 每局都有一笔固定成本，归因时必须扣掉

配装 1 和配装 2 实测内容完全一致（8 槽位 + 5 项物资：5.45 PS×215 自动购买、止血剂×4、医疗包×2、夹板×2、止血带×5），
每次进局固定缺口 `2 项 / 13,744 GB`（小背包 + 215 发弹药）。
→ 跑 3 局就是 **41,232 GB** 的固定支出；只看"战局收益"会把补给成本算成利润。
同时注意：这个缺口数会商人和仓库变化，**不是常量**，每轮开局前要重新读一次。

### 21. 「面部」不是命中部位，是叠在头部的第二层护甲；且配装模板只含 8 槽

命中部位只有 头 / 胸 / 腹 / 左右臂 / 左右腿，**没有"面部"这一格**。`面部` 是独立装备槽，
其作用是给"头部"命中叠一层小护甲。实测两个数值（百科 → 物品详情 → 防护数据）：

| 装备 | 防护等级 | 覆盖 | 耐久 | 钝伤/跳弹 | 惩罚（移动/人机/感知/隐蔽） |
| --- | --- | --- | --- | --- | --- |
| SSh-68 钢盔（现役） | 2 | 头部 85% | 30 | 30% / 15% | 0 / 1 / 0.05 / 0 |
| K6-3 防弹面罩 | 1 | 头部 40% | 20 | 20% / 10% | 0 / 1 / 0.2 / 0 |

→ 面罩的收益是"头部 40% 的命中改由 1 级护甲结算"，代价是人机工效 −1、感知 −0.2、0.4 kg。
而且全游戏只有 1 种面罩，描述写明 `可挂载在 K6-3 头盔上` —— 戴 SSh-68 时**装不上**。

配装模板为什么不含面部：`/stash` 的出战是 **11 个槽位**，配装弹窗里是 **8 个槽位**
（头部 / 耳机 / 防弹衣 / 胸挂 / 背包 / 主武器 / 副武器 / 近战）。
差的三个是 `面部` / `腰带` / `安全箱` —— 它们不在模板里，属于"加载配装时不会被改动"的槽位。
**未能验证**的部分：无法制造"已装备面部"的状态去测试保存（唯一面罩与现役头盔不兼容），
所以"配装绝对存不了面部"仍是推断，不是实测。

### 22. 外部建议必须回游戏核对数值（实测抓出 4 处错）

别人（含其他 AI）给的配件/弹药建议，数字要以**百科 → 物品详情**为准。实测抓到的错：

| 外部说法 | 实测 |
| --- | --- |
| AK PBS 消音器 `人机 +5` | **人机 −5**（`响度 −32`、`后坐 ×0.9`） |
| `军需升 L2 需要角色 5 级，你还差一级` | 军需**已是 LV 2**，角色已 LV 5 → `5.45 BT` 当时就能买 |
| `握把和枪托在军需 L1 根本没货` | 军需页**有货**：AK 斜角握把 10,901、AK 枪托 7,695 |
| `PS 弹最优射程 100m，超过就是浪费回合` | AK-74 基础射程 `100–400 m`；`1P87` 最佳 100/有效 400、`4 倍镜` 最佳 300/有效 600 |

弹药实测：`5.45 PS` 伤害 32.3 / 穿深 **25** / 护甲伤害 35%；`5.45 BT` 伤害 31.45 / 穿深 **34** / 护甲伤害 40%。
商人价：PS 30 发 128 GB、BT 30 发 333 GB（≈ +1,469 GB / 215 发）。

### 23. 武器详情里的「无兼容配件」不等于「没有兼容件」

AK-74 有 6 个配件槽：`枪口 / 瞄具 / 弹匣 / 握把 / 枪托 / 护木`。实测现役枪 `0 件已安装`。
详情页在 枪口 槽列了 `AK PBS 消音器`、弹匣 槽列了 `AK 45 发弹匣`（这两件正好在仓库里），
其余四槽显示 `无兼容配件` —— 而百科里 `4 倍瞄准镜` 的适配槽位写着 `AK 瞄具`、`AK 枪托` 写着 `AK 枪托`。
→ 这两处矛盾的唯一合理解释是：详情页只列**仓库里现有**的兼容件，不是"游戏内没有"。
（仍是推断，未实测；要证实只需买一件 AK 斜角握把试着装。）

### 24. 阵亡的通用模式：**打不穿 = 必死**（两局死亡都是这个形状）

11-10 10:40–11:00 那轮 3 局基线里死了 2 局，收尾日志几乎同构：

- 交通枢纽（293 回合，被玩家「红茶」打死）：
  `[292] 罗觉觉 在 165 米处对 红茶 开火 6 发，其中 1 发命中。 胸部 ×1 2伤害 胸部护甲拦下子弹。`
  `[293] 红茶 从 157 米外射向 罗觉觉 2 发子弹，命中 2 发。 胸部 ×1 40伤害 腹部 ×1 40伤害`
  → 我们 6 发只造成 **2 伤害**，对方 2 回合打掉约 200；`红茶 取下 罗觉觉 的狗牌`（玩家）。
- 机场（163 回合，被 AI 'Dmitri Orlov' 打死，同时被 3 个 AI 围攻）：
  `[162] … 胸部 ×1 3伤害 胸部护甲未被穿透。` → `[163] 罗觉觉 被 Dmitri Orlov 击毙。`

共同点不是"距离太远"或"血量阈值"，而是**穿深不足**：`5.45 PS` 穿深 25 / 护甲伤害 35%，
打在带护甲的对手身上只掉 2–3 血；而我们的对手能稳定打穿 PACA + SSh-68。
→ 结论：**先换 5.45 BT（穿深 34 / 护甲伤害 40%，+1,469 GB 每 215 发）**，再谈别的参数。

顺带修正一条推论：远距离对射**不是**一律亏。`06:09:28` 那局在 95/104/114 米打 AI 是赚的（+210,740）；
亏的是**对玩家 + 中远距离 + 打不穿**这个组合。所以"按距离脱战"是错的方向，"按能不能打穿"才是对的。

### 25. 自动出售是否生效，用"仓库件数差"验证

不用等隐藏日志，两条算术就能证：

- 第 1 局带回 `FIR 28 件`，仓库从 `103 件` 只变成 `107 件` → 约 24 件被卖掉
- 现金对账：`1,399,260` +239,100（第 1 局）−123,900 −176,100（两局阵亡）−41,232（3 局配装补给）
  = 1,297,128；实测 `1,352,868`，差 **+55,740** → 就是自动出售的收入

（阵亡两局的东西丢在局里，不进仓库，所以只算第 1 局。）

### 26. `analyze-log` 的统计陷阱：装填混入敌人、日志被截断、玩家名识别失效

日志里敌人的换弹也写成 `已经换好弹`、敌人的射击也写成 `开火`，正则一并统计进去了：
实测 08:55 那局 `装填 0` 却有 7 次开火行；365 回合那局 `装填 36`（≈1,080 发，远超随身 215 发）。
→ 这两个指标只能当"交火强度"的粗略代理，**不能用来做弹药预算**。要算弹药必须换成只匹配自己名字的正则。

另外两个同源的统计陷阱（都已修，记下来免得再踩）：

1. **详情页并不渲染全部日志**。293 回合的局只渲染 112 条、332 回合的局只有 119 条（首条是 `[8]`、末条是 `[293]`），
