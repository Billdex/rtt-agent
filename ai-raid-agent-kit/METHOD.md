# METHOD · 通用方法与纪律（M / H 编号）

> **这份文件可以独立外发。** 它只回答"怎么做事"，不含任何账号的数值、地图选择或库存。
> 游戏事实 → `LESSONS.md`（G）；脚本与页面 → `scripts/TOOLING.md`（T）；**本账号**的取值与状态 → `progress/STATE.md`。
>
> 换一个账号使用时：G/T 直接沿用，M/H 直接沿用，只需重新填一遍「当前值」和「任务单」。

```
M       = 实验纪律（做实验时怎么才不骗自己）
H       = 人机边界（哪一步必须停下来等人）
运营手册 = 两线划分 / 一轮流程 / 变量白名单 / 检查表 / 决策规则 / 完成判据
附录 A  = 任务单骨架        附录 B = 判据分级与写回去向
```

# M · 实验纪律

> 违反任意一条，本轮结论**作废**——不是"打个折扣"，是作废。

## M-01 结算只说结果，日志才说过程

同样是"撤离成功"，原因可以是弹尽、缺药、容器满、到回合上限、策略主动触发。四种原因对应四种完全不同的修法。
**只看结算就会改错参数。**

- 归因必须引用日志原文（`[回合号] 原文`），不能写"应该是弹药不够"。
- 结局定位**取日志最后一条命中**：中段击杀日志里也常出现 `死亡` / `致命攻击`，取第一处会把"击毙敌人"当成"本局阵亡"。
- 同一件事有多种写法，别只匹配一种：

| 概念 | 见过的原文写法 |
| --- | --- |
| 弹尽 | `已无弹可用` / `没有可用子弹` / `弹药耗尽` |
| 撤离成功 | `已完成撤离` / `已撤出战局，带出物资价值 N` / `成功撤出；带出价值：N` / `撤离成功，带出物资价值 N`（同一批 10 局出现 4 种） |
| 提前离场 | `【匆匆撤离】…本局经验减半` |
| 阵亡 | `阵亡` / `倒地身亡` / `因…的攻击死亡` / `遭到 'X' 的致命攻击` |

## M-02 一次只改一个变量

- 同一轮里既换地图又改撤退线又换配装，收益变化无法归因。
- 每一项改动必须能写成"**因为第 X 局的哪条日志**"，写不出来的不许改。
- 明知会失去可归因性仍然要同改两项时（例如时间成本不允许），必须在任务单里**显式标注"本轮结论不可拆分"**，
  并在结论里只采信能单独归因的那一半。

## M-03 主指标必须用全样本

同一张图，不同样本能算出相反方向。典型形状（本账号 2026-11-10 样本，明细见 `progress/report.md`，换账号需重测）：

| 样本 | GB / 回合 |
| --- | --- |
| n=4 子集 | 1,619 |
| n=8 全样本 | **1,083** |
| 新配装 n=2 | 886（此行本身违反 M-09） |

曾经差点用 n=4 宣布"提升 110%"，换全样本变成低 18%。

- 报数字必须带 **n + 时间范围**，并且用日志产物全量重算，不许手抄。
- 单局极值先当离群值，n≥3 再谈趋势。
- `收益/回合` 的分母是回合数，长短局混算要标注。

## M-04 外部建议必须回游戏核对

别人（含其他 AI、含玩家口传）给的数值，以**百科 → 物品详情**为准。**核对成本 1 分钟，验证成本 1 局。**

## M-05 "点了"不等于"生效了"

- `element.click()` 不做命中测试；Playwright 默认 dismiss 原生对话框。所以"日志显示已点"可能什么都没发生。
- 每个写操作都要一个**独立的成功判据**：卡片消失 / 重载后值还在 / 携带总价值增量对得上 / 仓库件数差。
- 账目核对同理：同一页连读两次不算证据，换页重读。

## M-06 证据分级：实测 / 推断 / 猜测

汇报与结案时必须标注，不许混写：

| 级别 | 定义 | 能否写进知识库 |
| --- | --- | --- |
| **实测** | 有日志原文或脚本输出，可复现 | 能 |
| **推断** | 有间接证据，缺一条直接验证 | 能，但必须标 `（推断）` 并写清"缺哪一条验证" |
| **猜测** | 只是解释得通 | **不能**；进假设表 |

## M-07 假设台账 + WIP = 1

- 同时只允许 **1 个活跃假设**，其余排队（台账在 `progress/STATE.md` §1）。
- 每个假设必须有：验证动作、单一变量、可区分的判据（"至少 2 局里能区分三种猜测之一；分辨不出来就换变量"）。
- 假设结案后才能开下一个；**分辨不出来也算结案**（写"未区分，放弃该变量"），不许无限挂起。
- 这是防止"6 个变量并行、每轮只推进一点点、人类感觉原地打转"。

## M-08 结论要能写成"触发器 → 动作"

不能写"看情况调整"。必须形如：

| 信号 | 动作 |
| --- | --- |
| 本局阵亡 | 撤退血量 +10、容器撤离阈值 −10 |
| 收益 < 目标 且未死 | 先读日志；日志里没有"无弹/缺药"就**不许**动参数 |
| 连续 2 局低于目标 | 换地图或换策略，停止微调 |
| 出现无弹 | 补到 3 局用量 |
| 交火占全局 > 50% | 先改接战距离，再考虑装备 |

写不成这个形状的"经验"，说明还没想清楚，先别写进任何知识文件。

## M-09 配装是"约束变量"，不进收益指标

配装同时改变"打不穿"和"收益密度"，所以：

- **配装永远不参与 `收益/回合` 的对比**（用一个被它自己污染的量表去量它）。
- 配装只回答三个**约束**问题，都有布尔判据，可离线判：

| 维度 | 判据（只数计数，不算钱） | 有证据才升 |
| --- | --- | --- |
| 打不穿 | 我方命中被 `护甲拦下` / `未被穿透` / 单发 ≤ 3 伤害的次数 | ≥ N 次 |
| 弹药不够 | `已无弹可用` / `没有可用子弹` 次数 | ≥ 1 次 |
| 活不下来 | 阵亡前 1–2 回合的伤害行、`重出血` 次数 | 阵亡前一刻伤害 ≤ 5（说明是打不穿而非被围） |

- **两段式，别用批次**：① 先查现有日志筛（0 局成本）→ ② 只升一个维度，跑 **1 局**复验（三类计数归零 + 战前自检全 PASS + "无法补购"件数不增加）。
- 容量（背包/胸挂格数）**不属于配装单**：负重触发离场通常意味着"吃够了"，属于策略阈值问题。
- 好处：配装从收益指标里摘出来后，经营线与策略线才能真正并行，不再互相作废。

统计口径提醒：日志聚合里的 `命中` / `装填` 把敌人也算了进去，判据必须按"射向 `<玩家名>`"一侧过滤。

# H · 人机边界

> 这里列出的每一处，**AI 都必须停下来说一句具体的话，然后等人类动作**。
> 不允许"自己试三次看看"——每一次多试，代价是一轮数据、一件买不回来的装备，或一次经验减半。

## 通用规则

1. 到达边界 → 立刻停手，用**一句话**说明"我需要你做什么"，附上**已经确认过的事实**（不附推测）。
2. 人类动作完成后，AI 必须做一个**独立校验**（重载重读 / 换页读数 / 文件差异），不能假设"他说做了就是做了"。
3. 人类拒绝时 → 记录在任务单的「前置」里，换别的任务单，不要反复请求。
4. 不确定是不是边界时，**按边界处理**（多问一句的成本远低于错一步）。

## H-01 登录与会话

- **触发**：链路命令报错、页面出现"登录"字样、CDP 连不上且重启浏览器无效。
- **人类动作**：在弹出的独立 profile 窗口里自己登录。
- **AI 该说**："浏览器会话已失效，请在那个独立窗口里登录一次，完成后告诉我。我不会读取密码或 Cookie。"
- **校验**：链路命令能读出页面标题与正文。
- **红线**：永不索取 / 读取 / 保存密码、Cookie、Token；浏览器 profile 目录不提交、不外发。

## H-02 开局

- **触发**：任何要"开始跑局"的动作。自动加入开关一开就开始倒计时。
- **人类动作**（二选一）：确认配置已经改好并允许开启；或自己点开关。
- **AI 该说**："我打算开自动加入：N 局 / 间隔 N 分钟 / 资金下限 N（预估消耗 N GB）。确认后我再点开关。"
- **前置顺序**：**先改完配置 → 重载复核 → 最后开开关**。
- **校验**：重载后读开关状态与按钮文案；确认没有局在跑时才能开。
- **注意**：这是"点下去就跑 N 局"的放大器开关，**不走 H-04 的补足免审**，必须先报备。

## H-03 策略写入（滑杆 / 数字框 / 优先点位 / 高级模式）

- **触发**：要改策略页任何值、写优先点位、碰「高级模式」。
- **人类动作**：AI 改完后，人类**亲自重载一次确认**；优先点位建议直接由人类点（自动化易失败）。
- **AI 该说**："策略已改为 X（原值 Y），依据是第 N 局的原文 `…`。请刷新策略页确认这一项还在，并确认其余项没变。"
- **校验**：策略快照前后各跑一次，diff 只允许出现预期的那一项；`changeCount = 0` 就是没改成。
- **红线**：绝不勾「高级模式」（高级模式会接管表单，属破坏性开关）；绝不点非"保存"的破坏性按钮。

## H-04 花钱（补足免审，升级报备）

分界线不是金额，而是**"补足已设定的量"还是"提高设定"**。前者游戏自己也会做，审批不产生任何保护。

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| **补足 · 免审** | 加载配装补满缺口、自动补货、治疗、修甲 | 直接执行，事后对账 |
| **升级 · 报备** | 买新装备、升级仓库/设施、改配装设定值（如携弹 231→150） | 先报金额，等批准 |

- **免审的理由**：自动加入开启时，游戏自带的「进入前维护 / 战后自动出售 / 自动补货」本来就在无人值守地执行；
  AI 停下来问，人类也拦不住，只是把 B 线排成一队。真正的保险丝是自动加入的资金下限（值见运营层状态文件），不是逐笔审批。
- **免审的替代控制**（缺一不可，否则等于"放开了还不记账"）：
  1. **每笔留账**：动作后立刻读现金，核对 `现金变化 ≈ 战局收益 − 治疗 − 维修 − 补货`；对不上就停下查（G-17 的白买只能靠这条抓到）。
  2. **回退线不设统一数字**：不同账号现金规模、消费结构不同，固定金额/百分比都会误报。
     回退只由两个动态信号触发——
     ① 现金跌破**该账号自己**的资金下限（健康线，值见运营层状态文件）→ 停补货，按升级类处理；
     ② 连续两轮补足支出**显著高于该账号近期自身中位数**（由台账自然浮现，不预设倍数）→ 该类退回"报备"。
- **仍必须报备**：买装备（增量资产）、升级仓库/设施、改配装设定值、以及 H-02 开局开关。
  （开局一按就是 N 局，属放大器，不是"补足"，不适用本节的免审。）
- **校验**：现金增量与账目一致。补足类可能已经由自动化先花掉，"当场报价"不再适用，改以事后对账为准。

## H-05 不可逆资产操作

- **触发**：换胸挂/背包、清仓/出售、拆解、丢弃、使用一次性资产、出售钥匙/任务物。
- **人类动作**：确认对象清单。
- **AI 该说**："要清掉这 N 件（总价值 N GB，预计到账 N–N GB）。其中 X 是任务物 / 钥匙 / 买不回来的装备，我会保留。确认？"
- **固定保留**：钥匙、任务物、一次性资产清单（本仓库见 `progress/STATE.md` §2）、配装里"无法补购"的件。
- **校验**：换容器后看携带总价值与容器格数；清仓后看体积/件数差（M-05）。

### 免审例外：接任务 / 交任务

这两件**不进 H-05**。它们不是"丢资产"，而是确定性的收益动作，风险只有"库存被消耗"，而库存够不够可以当场读仓库判：

| 动作 | 为什么免审 | 唯一前置（自查，不是审批） |
| --- | --- | --- |
| 接任务 | 零成本，且把需求物加进 `keepNeeds` 保护名单（G-28）——不接才会被自动卖掉 | 无。看到「可接取」就接 |
| 交任务 | 奖励确定（实测单批 +196,500 GB / +2,085 XP） | 读一次库存：交完该物仍够 **1–2 局用量**（G-27 副作用 ①）；不够先补货再交 |

- **唯一仍需退回 H-05 报备的情况**：要交出去的东西里含钥匙 / 一次性资产 / 配装里"无法补购"的件。
- **记账**：交任务会同时改变现金与仓库估值，批次收益口径按"现金 + 仓库"记（G-01），不能只记现金。

## H-06 轮次目标与验收口径

- **触发**：每轮开工前；以及任何"要不要宣布改善"的时刻。
- **人类动作**：确认这一轮属于**哪条线**、唯一变量是什么、"改善"的判据数字。
- **AI 该说**："本轮任务单：线 A，变量 X（原 Y → 新 Z），判据 = 全样本 GB/回合 > N（当前 n=N，时间范围 …）。驳回或确认？"
- **校验**：任务单写进 `progress/tasks/<id>.md` 后才开始执行。
- **为什么必须有**：没有这一步，AI 会用"这一轮做了什么"当成果，人类得自己判断有没有用。

## H-07 自动化与游戏规则风险

- **触发**：首次在本仓库运行、或游戏更新了用户协议/反作弊提示。
- **人类动作**：自行确认是否接受账号风险。
- **AI 该说**："自动化托管可能违反游戏用户协议，风险需要你自己判断；我按你的决定执行或停止。"
- **红线**：不替人类做这个决定，不提供规避检测的方法。

## 反模式（出现过，别再犯）

| 反模式 | 后果 | 替代做法 |
| --- | --- | --- |
| 自动写入失败后连试 3 次 | 白耗时间，还可能写脏草稿 | 第 2 次失败就停，报 H-03 |
| 自己开自动加入"看看能不能跑" | 未经批准花钱、污染批次数据 | 先报 H-02 |
| 用脚本直点同名按钮 | 点了没反应，循环重启 | 只认最后一个同名按钮，点完校验状态 |
| 用结算数字推理原因 | 改错参数 | M-01 |
| "顺便"换一下配装 | 本轮实验作废 | 两线互斥 + M-02（一次一个变量） |

# 运营手册（两线 · 流程 · 检查表）

> 这一部分是"每天怎么干活"的**通用结构**：换账号只需改值，不必改结构。
> **账号具体选什么值、当前状态如何，写在它的状态文件里**（本仓库：`progress/STATE.md` §1–§3）。

## 1. 两条目标线，必须分开

| 线 | 目标 | 手段 | 成功长什么样 |
| --- | --- | --- | --- |
| **A · 策略迭代** | 全样本「收益/回合」上升，且可归因到**单一变量** | 读日志 → 归因 → 改 1 个参数 → 再读日志 | 数字变了，且能写成"因为第几局的哪条日志" |
| **B · 账号经营** | 配装 / 仓库 / 医疗 / 任务 / 现金随时可打仗 | 重装、治疗、清仓、接任务（多数**不需要**开局） | 健康线全部不越线 |

**两条线互斥**——同一轮只有一条是"主推进"：

| 情况 | 允许 | 不允许 |
| --- | --- | --- |
| 本轮是策略轮 | 做"维持"类动作（治疗/补弹） | 换装、改配装、改策略参数 |
| 本轮是经营轮 | 冻结策略参数与地图轮换；可清理、可升级 | 开局跑批次、改策略参数 |
| 维持动作意外改动了变量 | 在任务单里标注"本轮不可归因"，只记账不比指标 | 假装本轮是干净实验 |

理由：**换配装同时改变"打不穿"与"收益密度"**，混在一轮里本轮数据直接作废（G-10 是实例）。

**判线的唯一问法**：这次改动会让一个**游戏决策**变好吗？会 → A 或 B（看决策是"怎么打"还是"带什么/存什么"）；
只是让脚本能跑 → 工具。工具改动单独开单，不计入策略轮。

## 2. 两层产出，不要混

| 层 | 产出 | 验收方式 |
| --- | --- | --- |
| **方法层（可复用）** | 一套流程 + 判据 + 脚本，别人拿去也能跑 | 新人只看入门文档就能跑完一轮；判据是数字不是感觉 |
| **结果层（本账号）** | 某张图上的具体参数组合 | 全样本 GB/回合 提升，n 足够，且可归因到单一变量 |

## 3. 一轮的固定动作

```
0) 领任务单（附录 A）        → 唯一变量 + 判据数字 + 需要人类做的事
1) preflight                → 任一 FAIL 就停（属于线 B，先转过去处理）
2) strategy-snapshot        → 记下改动前的机器凭证
3) 开局（走 H-02）          → 优先游戏自带自动加入
4) 局中只读                 → 可刷新、可跳页，绝不点撤离类按钮
5) 结束：analyze-log        → 读日志尾部 + 结局定位取最后一条命中（M-01）
6) 归因 → 只改一个变量       → 写不出"因为第几局的哪条日志"就不改（M-02）
7) 结案：更新状态文件 + 过程记录 + 任务单
```

**局中盯进度**只用专用 watchdog 脚本，不要手写循环，不要用 `| tail` 判退出码。

## 7. 三类动作，别混着做

| 动作 | 定义 | 频率 | 是否需要开局 |
| --- | --- | --- | --- |
| **维持** | 治疗、补弹、补药、修甲、加载配装 | 每轮开工前 | 不需要 |
| **优化** | 换装、升级胸挂/背包/护甲、改配装绑定、点任务 | 有明确缺口时 | 不需要 |

## 8. 决策规则（避免"花钱买教训"）

1. **加装备前先问"这件死了还能不能买回来"**（G-05）。买不回来的按一次性消耗品记账，不当资产。
2. **换容器顺序**：先换容器 → 再从仓库把弹药药品塞回新容器（G-19）。顺序反了物资会跟着旧容器回仓库。
3. **配装改动必须"先穿成目标状态，再快照"**（G-18）。不要试图字段编辑。
4. **白买检查**：配装字段与身上实际穿戴不一致时，每次加载都会白买（G-17）。局内自动换装后回头对齐。
5. **仓库满先扩容再清仓**（G-26）：扩容易失原值，优于按 59–66% 折价甩卖。
6. **任务先接再捡**（G-28）：未接取的任务物不在保护名单里，会被自动出售。
7. **交任务免审，但先读库存**：上交类任务消耗存量（G-27 副作用 ①），交完该物须仍够 1–2 局用量。
8. **配装优化走两段式，不进收益指标**（M-09）：先查日志数"被拦下 / 未穿透 / 弹尽 / 阵亡前伤害"，
   有证据才升，升完只跑 **1 局**复验，判据是三类计数归零，**不看 `GB/回合`**。
   容量问题（背包/胸挂格数）不归配装单，归 A 线阈值（G-12 B 类）。

## 9. 完成判据（必须是状态变化，不是"我做了"）

| 任务类型 | 判据 |
| --- | --- |
| 重装 / 治疗 | 战前自检 0 FAIL · 槽位全满 · 缺口 0 项 |
| 清仓 | 体积回到上限 50% 以下，且总价值下降比例在预期区间内 |
| 接任务 | 任务扫描里该条从「可接取」变「进行中」 |
| 配装优化 | ① 日志筛：升级理由能写成"第 X 局被拦下 N 次 / 弹尽 N 次 / 阵亡前伤害 N"；② 1 局复验：三类计数归零 + 战前自检全 PASS + "无法补购"件数不增加 |

写完判据才能收工；数字没到就是没完成，不许写"基本完成"。

# 附录 B · 判据分级与写回去向

## 三级判据（开工前必须先想清楚）

| 级别 | 判据 | 结论怎么写 |
| --- | --- | --- |
| 无效 | 判据数字没动，或方向相反 | "该变量不影响 X，已排除" —— 这也是有效产出 |
| 有效但不可归因 | 数字变好，但同期有其他变化 | "疑似有效，需单独复跑一次" |
| 可结案 | 单一变量 + 全样本 + n 足够 | 写进 `LESSONS.md`，更新主指标表 |

「分辨不出来」也是合法结果：写"未区分，放弃该变量"并列进已结案，不许无限挂起。
