# SKILL：浏览器游戏托管与策略迭代（Raid Agent Ops）

> 给 AI 助手看的操作规约。人类读者请先看 README.md。

## 何时使用

用户希望你"替他玩"一款网页游戏（尤其是有自动化/策略引擎的战局类游戏），并持续迭代策略、汇报进度。典型信号：
- "你自己玩吧，跑几轮看看"
- "帮我调策略""看看收益为什么降了"
- 需要跨小时/跨天的连续自动运行

## 两条目标线（先判线，再动手）

| 线 | 目标 | 手段 |
| --- | --- | --- |
| **A 策略迭代** | 全样本 `收益/回合` 上升，且可归因到单一变量 | 读日志 → 归因 → 改 1 个参数 → 再读日志 |
| **B 账号经营** | 配装 / 仓库 / 医疗 / 任务 / 现金可打仗 | 重装、治疗、清仓、接任务（多数不需要开局） |

- **互斥**：同一轮只有一条线主推进。策略轮内不动配装与工具；经营轮内不跑批次、不动策略参数。
- **WIP = 1**：同时只有一个活跃假设，其余排队。
- **知识分家**：游戏事实 → `LESSONS.md`（G）；脚本与页面 → `scripts/TOOLING.md`（T）；实验纪律与人机边界 → `METHOD.md`（M / H）。

## 前置条件（缺一不可）

1. 本机装有 Chrome（或 Chromium）。
2. Node.js + `playwright-core`（只要 `pnpm add playwright-core`，不需要下载浏览器）。
3. 用户愿意在**独立 profile** 的浏览器窗口里自己登录一次——永远不要索取密码、Cookie、Token。

## 第一步：起一个可接管的浏览器

```bash
# 关键：--no-sandbox 常用于绕过外层沙箱与 Chrome 自身沙箱的冲突
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --no-sandbox --disable-crash-reporter \
  --user-data-dir="$PWD/chrome-profile" \
  --remote-debugging-port=9222 \
  --no-first-run --no-default-browser-check \
  "https://目标站点/"
```

- 窗口起不来时，先看是不是嵌套沙箱杀掉了 Chrome：加 `--no-sandbox` 试一次。
- 用 `curl -s http://127.0.0.1:9222/json/version` 确认 CDP 可用。
- 之后所有操作通过 `playwright-core` 的 `connectOverCDP` 连上去，不再启动新浏览器。

## 第二步：盘点"游戏自带"的自动化，别急着写脚本

这是最重要的一条经验。先找设置里有没有：
- 自动加入战局（间隔、局数上限、资金下限）
- 进局前自动治疗 / 自动维修
- 地图轮换、每图绑定策略与配装
- 战局结束后自动出售

**游戏自带的调度永远比外部脚本稳。** 外部脚本只负责：读状态、读日志、改参数、出报告。

## 第三步：建立安全基线（开跑前必须确认）

| 项 | 建议 |
| --- | --- |
| 局数上限 | 一次 3–6 局，到量自动关 |
| 资金下限 | 留足重配本钱（≥ 一整套装备的 0.7 倍） |
| 地图 | 先用最低难度、人数最少的图 |
| 撤退线 | 先保守，有数据支撑再放松 |
| 备份 | 改动前把原配置导出成 json 存档 |

## 第四步：每轮的固定循环

```
preflight（开机检查）
  → 进入战局
  → 局中可读可刷新，不碰「手动撤离」
  → 结束：读结算 + 读完整战局日志
  → 归因（弹药？药品？距离？密度？地图？）
  → 一次只改 1 个变量（WIP=1）
  → 记录到 report.md
```

## 第五步：迭代规则要写成"触发器 → 动作"

不能写"看情况调整"。必须形如：

| 观察到的信号 | 动作 |
| --- | --- |
| 本局阵亡 | 撤退血量 +10、容器撤离 −10 |
| 收益 < 阈值 且未死 | 先读日志归因；日志里没有"无弹/缺药"就不许动参数 |
| 连续 2 局低于阈值 | 换地图或换策略，而不是继续调参 |
| 日志出现"已无弹可用" | 补弹到 3 局用量 |
| 单局交火占用回合 > 50% | 缩短接战距离或提高脱战阈值 |

## 第六步：结束时要交付的东西

- `report.md`：每局一行（时间/地图/结局/击杀/收益/死因），加"策略改动历史 + 原因"
- `raid-analysis.json`：日志级统计（开火、命中、落空、被击中、缺弹、缺药、搜刮动作）
- 一段 3–5 条的结论，区分"有证据"与"猜测"

## 硬性禁忌

1. **战局进行中不要误点"手动撤离"**。整页刷新与 `page.goto` 跳路由是安全的，不会断连也不会判离场；真正导致"提前离场、经验减半"的是点到撤离类按钮。点按钮前先读文案。
2. **不要索取或读取密码/Cookie**。要登录就让用户在独立窗口自己登。
3. **不要凭结算数字猜原因**，一定读战局日志：结算只说结果，日志才说过程。
4. **一次只改一个变量**，否则收益变化无法归因。
5. **不要假设"自动购买"免费**：加载配装会按缺口扣钱，要核对现金变化。
6. **不要同时验证多个变量**。一次一变量、WIP=1；写不成"因为第 X 局的哪条日志"的改动不许做。
7. **不要把"跑了 N 局"当成果**。成果是判据数字变了（带 n 与时间范围）。
